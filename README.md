# 拾页 · 自媒体工作台

一个以 Obsidian Markdown 文件为底座的个人创作工作台。包含 Obsidian 桌面插件和使用同一套 React 界面的本地网页。数据直接写入知识库，不依赖数据库、云服务或浏览器 LocalStorage。

## 本地启动

需要 Node.js 22 或更新版本。

```bash
npm install
npm run seed       # 可选：在 local-vault 创建 20 条明确标记的示例资料
npm run dev
```

打开 http://127.0.0.1:5173 。省略 seed 就从空知识库开始；启动时会建立目录、模板和索引。重复运行 seed 不会覆盖已有示例。

连接已有目录：

```bash
VAULT_PATH="/你的/知识库路径" npm run dev
```

服务只监听 `127.0.0.1`，API 拒绝跨站访问与非 JSON 写入。目录里的实际资料、采集结果和 `.obsidian` 配置均不提交到 Git。

## 在 Obsidian 中使用

```bash
npm run build
```

1. 将 `release/creator-workbench` 文件夹复制到目标知识库的 `.obsidian/plugins/` 下。
2. 在 Obsidian 的第三方插件设置中启用「拾页 · 自媒体工作台」。仅在你确认信任本项目代码的知识库中启用。
3. 点击左侧工作台图标，或在命令面板执行「拾页 · 自媒体工作台：打开工作台」。
4. 插件默认把资料放在该知识库的 `拾页知识库/` 子目录。设置中可以改为其他相对目录；留空表示知识库根目录。切换目录不会搬迁文件。

本项目的 `local-vault` 也可以直接作为 Obsidian 知识库打开，插件资料目录设置留空即可。插件与网页读写同一批资料；Obsidian 插件本身不需要启动 Node.js 服务。

## 已实现

- 首页完整展示当前批次的全部热点，按实际发布平台分组、筛选；历史热点可按采集批次回看。候选选题单独展示，最多三个。
- 自然绿色创作空间：本地主视觉大图叠加实时时钟、秒数和日期；侧栏展示候选选题，以及由笔记采集/更新时间整理的最近动态。支持桌面三栏与窄屏布局。主视觉随网页构建发布，Obsidian 插件内嵌图片，不依赖外部图片链接。
- 统一输入框支持查知识库、选择 RedFox 平台或 Bing 找热点、把自媒体链接交给 Codex 分析。关键词查询直接在页面展示结果，多关键词用空格分隔；自然语言问题可交给 Codex 阅读索引与原文后回答。
- 个人经历、感悟、案例、稿件、数据与复盘继续保留在次级导航。
- 选题的五个状态与拖拽看板，也可以在详情编辑状态。
- 卡片 / 列表视图、全文搜索、状态筛选和排序。
- 新建和编辑 Markdown 资料、标签、摘要、计划日期、平台和来源链接。
- 资料关联及反向引用；从资料创建选题时自动保留关联。
- 从界面移动到其他分类，保持稳定 id 与引用，禁止覆盖同名文件。
- 发布记录、数据快照和复盘。数据记录要求平台、采集时间、统计窗口及关联发布记录。
- 根目录、一级目录和细分类的 `INDEX.md` 自动维护；支持手动重建及独立索引命令。
- Obsidian 文件事件 / 本地文件监听自动同步；损坏属性和重复 id 会显示诊断。
- 基于原文件完整内容检查保存版本。发生冲突时保留编辑内容，提供最新文件对照。
- 少数派、阮一峰网络日志、Hacker News 的 RSS / Atom 收集，每次最多 20 条，按来源 URL 去重并进入收集箱。
- Codex 任务入口：分析选题、从经历找选题、打磨稿件、复盘表现；详情任务携带当前资料路径、id 与关联阅读要求。

Codex 使用官方 `codex://new?path=...&prompt=...` 深链接。点击后预填工作目录和任务，**由用户发送后才开始执行**；AI 实际写回 Markdown 后才会同步到看板。知识库关键词搜索在本地执行；自然语言问答、热点研究和链接分析由 Codex 执行，尚未在工作台内嵌 AI 对话。

热点研究通过 Codex 中已配置的 RedFox MCP 连接进行，支持抖音、小红书、公众号、快手、视频号、Bilibili、今日头条、TikTok、X / Twitter、YouTube、Instagram；每次明确选择一个平台，也保留 Bing 网页搜索入口。工作台只生成任务，不代表平台已连接或已采集。凭据保存在 Codex 客户端，不能写进知识库或仓库；连接不可用时必须如实报告。仅将用户输入关键词发送到外部搜索，核对最近 30 天的原文发布时间，最多保存 10 条热点与 3 个选题。热点使用 `platform`、`collection: daily-ai-tools` 与 `batch: YYYY-MM-DD` 标注来源和批次；新批次核验成功后将旧热点移入 `20_知识素材/热点资讯/历史热点/YYYY-MM-DD/`，保留稳定 id 和引用，失败则保留当前批次。来源在当前与历史间按链接去重。默认手动运行，不创建定时任务。

## 知识库结构

```text
INDEX.md                         # 总入口与检索导航
AGENTS.md                        # AI 写入规则
00_收集箱/
10_个人资料/
  个人定位/ 工作经历/ 项目实践/ 生活经历/ 个人感悟/
20_知识素材/
  热点资讯/ 案例拆解/ 参考资料/ 方法技巧/ 工具资源/
30_内容创作/
  选题库/ 稿件库/
40_发布运营/
  发布记录/ 数据记录/ 复盘总结/
90_系统资源/
  模板/ 附件/
```

每个主要分类内有 `INDEX.md`，列出标题、相对链接、id、分类与状态、摘要、标签、关联 id 和更新时间。自动区域使用 HTML 注释标识，只替换该区域；已有人工内容会保留。现有 `AGENTS.md` 不会被覆盖。

笔记示例：

```yaml
---
id: content-001
title: 用 AI 做保价工具的实验
category: topic
status: 创作中
summary: 从一个生活问题讲清工具的价值和局限
tags: [AI, 个人实践]
related: [experience-001]
platform: 小红书
due: 2026-10-08
created: 2026-09-30T08:00:00.000Z
updated: 2026-09-30T08:00:00.000Z
---
```

正文保留完整表达。`related` 使用稳定 id，不依赖标题或文件名。分类以所在目录为准，移动后编号不变。状态固定为 `灵感 / 待创作 / 创作中 / 待发布 / 已发布`。额外 YAML 属性和注释在编辑时保留。

发布与数据可使用 `source`、`published`、`collected`、`window`、`views`、`likes`、`comments`、`saves`。界面不把不同平台或不同时点的快照加成一个误导性的总数。

## 开发与验证

```bash
npm test                # 真实临时目录上的文件、冲突、索引、RSS 与链接测试
npm run typecheck
npm run build           # 生成浏览器构建和 Obsidian 插件
npm run index           # 服务未启动时重建默认示例库索引
VAULT_PATH="/知识库路径" npm run index
```

源码：`src/core` 是共享文件模型与索引，`src/ui` 是 React 界面，`src/obsidian.tsx` 适配 Obsidian Vault API，`server` 适配本地文件系统与预览 API。

`dist/` 是前端静态构建，不能单独部署后读写本地目录；本地网页需要 `npm run dev` 所提供的文件 API。正式日常使用可直接安装 Obsidian 插件。

## 当前范围

桌面优先，支持窄窗口布局。RSS 仅保存条目摘要与原始链接，不抓取付费正文，不自动将热点视为已验证事实。暂不包含社交平台自动发布、自动拉取账号经营数据、附件上传和定时采集。删除资料可使用 Obsidian 自带的回收站操作。

Obsidian 保存使用 `Vault.process` 检查并原子更新正文与属性。本地网页使用串行写入、完整版本比较和临时文件替换，能检测已发生的外部修改；它不是跨进程文件锁，多台同步工具同时写同一笔记时仍应避免并发编辑。

原文变更会更新索引。服务或插件未运行时，重新打开工作台或运行索引命令即可补齐。`example: true` 的示例不得用于声称用户有相应真实经历。
